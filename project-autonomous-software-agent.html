Autonomous Software Engineering Agent

Enterprise-Grade Autonomous Multi-Agent Software Delivery Platform

An autonomous AI software engineering platform that automates the software delivery lifecycle from Jira issue selection through repository analysis, code generation, testing, GitHub Pull Request creation, Jira completion, and Slack notification.

View GitHub Repository ← Back to Portfolio

Project Overview

The Autonomous Software Engineering Agent simulates an AI Software Engineer capable of understanding work items, analyzing repositories, retrieving relevant context, generating production-ready code, validating modifications, executing automated tests, reviewing changes, and delivering completed implementations.

The system combines traditional software engineering automation with LLM-driven decision making through a modular multi-agent architecture.

Problem

Modern software development requires engineers to move between multiple systems: Jira for requirements, GitHub for source code, testing infrastructure for validation, code review tools for quality checks, and communication platforms such as Slack.

This project explores how an AI-driven engineering system can coordinate these activities and execute the complete workflow with minimal human intervention.

Multi-Agent Architecture

The platform separates responsibilities across specialized agents rather than relying on one monolithic LLM workflow.

01

Planner Agent

Reads the Jira backlog, selects the next available story, prioritizes the work item, and transitions the issue to In Progress.

02

GitHub Agent

Handles repository cloning, branch creation, remote configuration, commits, and repository operations.

03

Repository Analyzer

Detects the programming language and framework, parses the repository structure, and prepares repository intelligence.

04

Repository Indexer

Indexes source code, extracts symbols, and builds the repository and dependency graph.

05

Retrieval Agent

Retrieves the most relevant files and symbols using semantic retrieval, symbol lookup, and dependency analysis.

06

Developer Agent

Converts the retrieved repository context and engineering requirements into an implementation strategy.

07

Coding Agent

Uses the configured LLM provider to generate complete repository files rather than isolated code snippets.

08

Patch Agent

Converts AI output into structured repository patches and prepares modifications for validation.

09

Patch Validator

Validates generated operations and prevents invalid repository modifications before changes are applied.

10

Reviewer Agent

Performs LLM-based code review across correctness, maintainability, security, performance, and code quality.

11

Tester Agent

Detects the project type, executes the appropriate test framework, and captures test commands, output, and pass/fail status.

12

GitHub Delivery Agent

Stages changes, commits the implementation, and pushes the feature branch.

13

Pull Request Agent

Creates the GitHub Pull Request with an AI-generated description, Jira reference, branch metadata, and review information.

14

Jira & Slack Delivery

Records implementation and test results in Jira, transitions the issue to Done, and communicates workflow progress through Slack.

End-to-End Workflow

1. Select Jira Story
Identify the next available software engineering task.
2. Move Story to In Progress
Update the Jira workflow state.
3. Clone Repository
Retrieve the target source repository.
4. Create Feature Branch
Create an isolated implementation branch.
5. Analyze Repository
Detect language, framework, structure, symbols, and dependencies.
6. Retrieve Context
Identify the relevant source files and symbols.
7. Generate Code
Use the selected LLM provider to generate implementation changes.
8. Validate Patch
Validate structured file operations before modifying the repository.
9. Apply Patch
Safely write the generated changes to the workspace.
10. Review Changes
Perform automated AI-based code review.
11. Execute Tests
Run the appropriate project test framework.
12. Commit & Push
Commit validated changes and push the feature branch.
13. Create Pull Request
Automatically create a GitHub Pull Request.
14. Update Jira & Notify Slack
Record implementation results, update Jira, and notify the engineering team.

Repository Intelligence

One of the core capabilities of the platform is repository understanding.

Language Detection

Detects the programming language used by the target repository.

Framework Detection

Identifies the project's framework and development environment.

Symbol Extraction

Extracts relevant source symbols to improve contextual retrieval.

Dependency Graph

Builds dependency relationships between repository components.

Context Retrieval

Instead of providing an entire repository to an LLM, the retrieval layer identifies the most relevant context required for the requested software change.

Semantic Retrieval

Retrieves files related to the requested implementation task.

Symbol Lookup

Locates relevant classes, functions, and source symbols.

Dependency Analysis

Identifies related components required to understand an implementation.

Context Reduction

Reduces unnecessary repository content before sending context to the LLM.

Provider-Agnostic LLM Architecture

The platform abstracts the LLM provider so that the software engineering workflow does not depend on a single model provider.

OpenAI Claude Gemini Ollama Mock Provider

This provider abstraction allows the same software engineering workflow to operate with different models depending on availability, cost, capability, or deployment requirements.

Automated Code Quality

Patch Validation

Generated modifications are represented as structured operations and validated before being applied.

AI Code Review

Reviews generated implementation for correctness, maintainability, security, performance, and quality.

Automated Testing

Supports pytest, unittest, npm test, Maven, and Gradle workflows.

Automated Software Delivery

After successful implementation and testing, the platform continues through the delivery workflow automatically.

GitHub

Commit changes, push feature branches, and create Pull Requests.

Jira

Attach implementation results, record test results, add the Pull Request, and transition completed issues.

Slack

Notify engineering teams about workflow start, testing, Pull Request creation, completion, or failure.
